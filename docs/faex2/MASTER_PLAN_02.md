## 2. Обязательные правила исполнения и правовые границы

Действуют для **каждой** задачи Волн 0–5, фоновой гигиены и R&D:

1. **Контроль владельца и откат:** ни одна сборка, стендовое GPU-окно, смена продакшена или `git push` не выполняются без явного согласия владельца. При каждом стендовом окне сохраняется путь мгновенного отката на действующую стабильную роль (`b81812aa` / `be242d70`), долгие прогоны выполняются устойчиво к обрыву SSH, сырые логи (включая неуспешные) сохраняются.
2. **Изоляция изменений:** один кандидат — один вопрос; численные изменения (не-побитовые) никогда не смешиваются в одном кандидате со структурными/графовыми. Сравнение скорости — строго matched pair (`контроль ↔ кандидат`) с порогом **5 % и 3 мс** на каждый запрос/фазу **без усреднения**.
3. **Успешные оптимизации становятся дефолтом** без лишних флагов (после прохождения соответствующих ворот качества).
4. **Правовые правила заимствований (строго!):**
   * **`strixite` (GNU AGPL-3.0):** запрещено переносить **ни одной строки кода** (наш `gufo serve` — сетевой сервис). Разрешены **только инженерные идеи**, реализуемые с нуля под архитектуру Gufo.
   * **`tubo`, `Q6dense`, `gufo-laguna`, `llama.cpp` (MIT):** перенос кода разрешён при сохранении copyright-нотисов, обновлении `NOTICE` / `THIRD_PARTY_NOTICES.md` и `VENDOR.md` (при правках `mmq`).
   * **Веса HuggingFace (`unsloth`, `Q6dense` и др.):** проверять лицензии карточек до скачивания на стенд.
5. **Чистота Git:** небольшие Conventional Commit'ы на русском, только свои пути, локальная noreply-идентичность; обновление [CONTEXT.md](CONTEXT.md) и [CHANGELOG.md](CHANGELOG.md) после каждого значимого этапа.

## 3. Единый порядок дальнейших работ (Волны 0 → 5)

Порядок выстроен **строго по физическим зависимостям** (см. [ROADMAP_SPEC_NEXT_02.md](ROADMAP_SPEC_NEXT_02.md) §2 и §12), чтобы исключить любую двойную работу:
* сначала снимаем полную карту ядер/экспертов и утверждаем `Q1` (**Волна 0**);
* затем забираем бесплатные и побитовые ускорения базы + `Sparse` (**Волна 1**);
* затем обрушиваем маржинальную цену строки верификации $c_{\text{row}}$ с `5,3 мс` до **`≤ 2,5 мс`** и переводим DeltaNet-prefill на WY-чанки (**Волна 2**);
* только после падения $c_{\text{row}}$ включаем супер-спекуляцию и динамические деревья **EntMTP** (**Волна 3**);
* затем один раз проектируем новый формат снапшотов/кэша (якоря + сегменты + `Restore` + `resume_hint` + `Stint`) и апгрейдим точность весов (**Волна 4**);
* и финализируем ре-профилем Т10, мега-ядром и автосертификацией (**Волна 5**).

* **Эффект и качество:** **+10–15 % на классе `tool` и редактировании кода**, **100 % lossless** (`output_sha256` 33/33 + $\chi^2$-тест).

#### `W3.4` `[Код/Спекуляция]` Перекрытие `verify → draft` + «Острый» черновик ($t_{\text{draft}} < t_{\text{request}}$)
* **Перекрытие:** после verify шага $N$ скрытое состояние и argmax уже на GPU — при зазоре `top1 − top2 > 0,8` (выше MoE-шума `0,09–0,82`) ставить head-pass MTP шага $N+1$ в очередь GPU до CPU-решения (редкий промах откатывается через готовый `proposal_checkpoint_`) → **+5–13 %** (побитово).
* **Острый черновик:** параметризовать температуру $t_{\text{draft}}$ в `LaunchMtpRowTopK` (`W1.5`); 100 % lossless для любого $q$, проверить знак эффекта на одном прогоне `SpeculativeStats` + `sampled_mtp_distribution_test` ($\chi^2$).

#### `W3.5` `[Код/Спекуляция]` `SpecFit / S2-MoE` + `EntMTP` + Кросс-сессионная verify-пачка *(эволюция `T7`)*
* **Компонент А (`SpecFit / S2-MoE`, arXiv:2610.15417 / 2608.15018):** при выборе 2-го кандидата / ветки верификации оптимизировать **пересечение активированных экспертов MoE** с основным кандидатом (минимизация объединения экспертов) → **+15–25 % на C2–C4**, **100 % lossless**.
* **Компонент Б (`EntMTP` + Cost Gate `T7`):** заменить `rolling_window = 16` и жёсткий `GUFO_MTP_MOE_MAX_COHORT = 4` на мгновенный контроллер по `head-top1`, зазору цели `top1 − top2` и когорте `C1..C8` (плюс порог отсечки `0.5` из `Q6dense` и офлайн-калибровка на пошаговом `--capture-dir`):
  * высокая уверенность → цепочка глубины `2–3` (+15–18 % на `tool`/коде);
  * средняя уверенность **и подтверждённое $c_{\text{row}} \le 2,5\text{ мс}$** → узкое 2-веточное SpecFit-дерево;
  * низкий зазор цели / перегрузка когорты → `SkipDraft` (`AR`-шаг).
* **Компонент В (Кросс-сессионная verify-пачка):** объединить target-строки верификации разных сессий в один запуск `ForwardVerificationBatch`, чтобы ~1,6 ГБ весов читались один раз на все сессии → **возврат MTP на 6–8 пользователей (`178 → 210–250+ tok/s`)**, побитово.

### Волна 4. «Дерево сессий», `TTFT ≈ 0`, память на уровне `llama.cpp` и точность весов

*Цель волны:* один раз спроектировать чистое новое поколение подсистемы снапшотов/кэша (без двойной переделки формата!), закрыть зазор по памяти и поднять качество весов выше `llama.cpp` без потери скорости.

#### `W4.1` `[Код/Кэш]` Per-block / Chunk-aligned SSM-якоря (`SnapshotPurpose::kAnchor`)
* **Механизм:** сохранять только 30 слоёв DeltaNet+conv (**63,75 МиБ = 0,16–0,6 мс копии**, в 40 раз меньше KV!) каждые `4K–8K` токенов в ходе длинного prefill (`prefill_chunk.cpp`), а также расширить `kSsmReplayCapacity` с `16` до `32–64`.
* **Эффект и качество:** прерываемый prefill без квадратичного хвоста в C4 (≤ 4 с вместо 32 с повтора) + хит продолжения в любой точке 64K-истории (правка середины диалога OpenCode / compaction); **100 % побитово**.

#### `W4.2` `[Код/Кэш/API]` Потоковый `Restore` + Сегментная континуация + `resume_hint` + `Stint` + `MEMTRIM` *(бывш. `T12a` + кэш-революция)*
* **Пять связанных доработок единого формата снапшотов:**
  1. **Streaming `Restore`:** чтение снимков с диска чанками 8–16 МиБ с двухфазной проверкой checksum, zero-copy переносом (MIT `tubo`: `snapshot_copy.hip` / `hipHostGetDevicePointer`) и переиспользуемым `HostBuffer` *(идея `strixite`, 0 строк AGPL)*.
  2. **Сегментная континуация и дерево веток:** семантика cache-editing (`clear_at_least`, `prompt_cache_key`, закреплённый `System+Tools` + сегменты с TTL), copy-on-fork (наследуется только новое GDN-состояние без дублирования KV), межсессионный content-addressed `prefix_index` с refcount (общие 20+ схем инструментов хранятся единожды на всех).

## 5. Исследовательская лаборатория (R&D — строго изолированный стенд)

Смелые гипотезы с высоким риском и правом на отрицательный результат. **Никогда не смешиваются с боевыми волнами:**

* **`R1` (DeltaNet-память):** *Re-baseline* (фоновый chunked prefill последних 2–4K токенов раз в 16K в банк B против decode-дрейфа) и *Recency Re-priming* (расширенный replay-лог 512–1024 в BF16, 0,6 мс рескан в банк B для усиления self-needle; строгий контроль двойного decay).
* **`R2` (ультра-сжатие веток и чекпоинтов):** `SuffixReplay` (arXiv:2609.33477, хранение веток `0,36–0,51×`, через `Q1`) и сжатие *чекпоинтов* DeltaNet (`BF16` / `STEPQuant 6-bit` / `DASC`); **активное состояние в декоде остаётся в FP32** (FP8 запрещён).
* **`R3` (альтернативный draft):** дешёвый спайк training-free *Self-Draft MoE* (`DraftExpert` / `SpecMoE`: `shared + top-1`) против встроенного MTP1; дальний горизонт — обученная голова уровня `EAGLE-4`.
* **`R4` (`Steering-векторы`):** 2-дневный спайк `h += α·v` на 2–3 слоях для усиления точности tool-вызовов (побитовое совпадение при $\alpha = 0$, оценка на Б2).
* **`R5` (бывш. Этап 5, СТРОГИЙ КАРАНТИН — NPU XDNA2):** штатное включение NPU prefill (`QwenNpuFfn`, код уже в ветке) — **только** после внешнего фикса Data Fabric MC28 (`ROCm/TheRock#8709`, `amd/xdna-driver#1605`, SMU ≥ 100.9.0) или перехода на Gorgon Halo, с обязательными защитами `649824af` (non-finite fallback), таймаутами `run.wait()` и fingerprint `.xclbin`. Гипотеза обхода runtime-PM без фикса AMD — строго отдельный эксперимент, никогда не приближать к продакшену.
