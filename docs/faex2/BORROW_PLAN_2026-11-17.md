## Блок D. KV-кэш `Q8_0` (Этап 3; вердикт «ДЕЛАТЬ», ~300–500 строк) с уроками tubo

**Общие решения (до кода, по образцу §8.1 NEXT_STAGE_SPEC + уроки tubo §5.3 отчёта):**

* Энум `QwenKvCacheStorage` **дописывать в конец**, не вставкой: в persisted-снапшоте хранится числовое значение энума; precision-bound в `arena.cpp` поднять до последнего энума (иначе свой же билд отвергнет свой снапшот).
* Смешанный кэш → таблица по плоскостям (`QwenKvLayerFormat`), не один энум.
* Одна функция смещения блока на writer+reader (урок `QwenKvHeadBlockOffset`), CPU-оракул кодека обязателен: байтовая идентичность host/device.
* Формат блока: GGML `Q8_0` (34 B / 32 знач., FP16-scale) — согласуется с `DequantizeQ8_0ToBf16Kernel`, который уже есть в дереве; вопрос «scale из FP32-результата или из округлённого FP16» зафиксировать письменно и не менять.
* K-шкала: рассмотреть поканальные масштабы на группу 32 (идея kv8 strixite, −42 % ошибки на K) как вариант против чисто блочного; решить на CPU-оракуле + holdout до ядра.
