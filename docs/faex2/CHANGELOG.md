# Журнал изменений Gufo FAEX2

Наш журнал форка. Корневой [CHANGELOG.md](../../CHANGELOG.md) сохранён как журнал исходного Gufo. Новые записи сверху; фиксировать результат, проверки, ограничения и решения, а не стенограмму чата. Текущее состояние — [CONTEXT.md](CONTEXT.md).

## 2026-11-09

### Настройки GitHub и защита faex2

- После явного согласия владельца и его входа в Chrome основная ветка изменена с `fork-enhancements` на `faex2`, Issues включены.
- Создан Branch ruleset `protect-faex2` (ID `26885069`), режим `Active`, точное включение `refs/heads/faex2`, без исключений веток и с пустым Bypass list. Включены только `Restrict deletions` и `Block force pushes`. Обычные push разрешены; обязательные PR/reviews/CI и другие дополнительные правила не вводились.
- GitHub показал успешное создание правила и применение к одной ветке `faex2`. Независимые GET-запросы API подтвердили default, Issues, `protected: true`, активное правило и эффективные типы `deletion`/`non_fast_forward`. Публичный API не возвращает Bypass list: его пустота проверена через интерфейс владельца, а не выведена из отсутствия поля.
- В административном интерфейсе Actions подтверждено выбранное `Disable actions`; менять настройку не потребовалось. Workflow permissions остались на чтение, создание/одобрение PR через Actions выключено; эти параметры не менялись.
- Опубликованный SHA остался `e6b99cfbab3dae88a2aabafd57cfe8a98701a5d6`. Push, PR, сборки и аппаратные тесты не выполнялись; FAEX2 не затрагивалась. Результат сохраняется локальным коммитом документации, без публикации.

### Первая публикация ветки faex2

- Владелец явно разрешил подготовленную команду публикации и поручил проверить SHA после отправки, отдельно запретив затрагивать FAEX2.
- Перед отправкой подтверждены чистое рабочее дерево, HEAD `e6b99cfbab3dae88a2aabafd57cfe8a98701a5d6`, noreply автора/создателя и отсутствие удалённой `faex2`.
- Согласованный push через разовый SSH URL успешно создал только `refs/heads/faex2` на указанном SHA. Использованы `--no-follow-tags --recurse-submodules=no`; постоянные настройки Git/SSH и pushurl не менялись.
- Независимое чтение через HTTPS `git ls-remote --symref` подтвердило точное совпадение SHA. Default осталась `fork-enhancements` на `0f1a7dbf9023c965ed8802fc16f30c2f69fb0a54`, тегов нет. PR не создавался, настройки форка не менялись.
- FAEX2 не затрагивалась, сборки/модели/аппаратные тесты не запускались. Эта запись и обновление CONTEXT сохраняются следующим локальным коммитом; разрешение на публикацию конкретной ревизии не использовано для повторного push.

### Аудит перед первой публикацией

- Проверены собственные изменения `6a107cf6..582d1d6c`: 27 файлов, 7 коммитов (пять реализации и два документации), без merge. Author/committer используют noreply; `git diff --check` прошёл.
- В 32 новых blob и 7 commit-объектах не найдено совпадений с использованными шаблонами секретов, личных путей/локальной сети и email вне noreply. Новых бинарных blob нет; проверяемые приватные пути отсутствуют в деревьях всех семи коммитов. `.local/` игнорируется и не включена в индекс.
- Известный прежний email не найден во всех 17 268 объектах, достижимых из проверенной вершины. Старые пять коммитов недостижимы; деревья файлов каждой пары старый/новый совпадают. Повторная очистка истории не выполнялась.
- Через `git ls-remote --symref` проверено текущее состояние собственного GitHub-форка: только default-ветка `fork-enhancements` на `0f1a7dbf9023c965ed8802fc16f30c2f69fb0a54`, без тегов. Для проверки предков загружены недостающие объекты через fetch без записи FETCH_HEAD, изменения веток и merge; прежние пять коммитов не входят в историю этой вершины.
- Границы: поиск по шаблонам и просмотр собственных изменений не доказывают отсутствие любых секретов в унаследованной базе; корректность модели, сборка и GPU/NPU не проверялись. Исходники не менялись. После итогового коммита документации повторить проверку обновлённой вершины; локальные скрипт и отчёт аудита сохраняются вне Git.
- Подготовлена схема публикации только закреплённого SHA в `refs/heads/faex2` через разовый SSH URL, без отправки тегов и изменения постоянных pushurl. Push требует отдельного согласия и не выполнен; FAEX2 не затрагивалась.

### Подтверждён SSH-вход в GitHub

- Владелец добавил отдельный публичный ключ в GitHub и загрузил ключ в локальный SSH-агент. Повторная проверка `ssh -T` с явным выбором ключа, `BatchMode=yes`, `StrictHostKeyChecking=yes` и `UpdateHostKeys=no` вернула приветствие об успешной аутентификации как `niiv0832`; код 1 ожидаем при отсутствии shell-доступа GitHub.
- Обновлены CONTEXT и непубличная локальная памятка. Следующий шаг — аудит перед первой публикацией; права записи в репозиторий этой проверкой не подтверждались.
- Push/PR не выполнялись, блокировка push сохранена. К FAEX2 не обращались; сборки, модели и аппаратные тесты не запускались. Настройки Git/SSH агент не менял, парольную фразу вводил только владелец в своём терминале.

### Самостоятельная документация и передача новой сессии

- Созданы CONTEXT, SPEC, DESIGN, BASELINE и этот журнал; в README/AGENTS добавлены точки входа и правила форка. Унаследованные документы, лицензия и исходники не удалялись.
- Назначены границы: движок/тесты/дизайн — здесь; состояние машины/deploy/личные материалы — в отдельном эксплуатационном проекте. Исторические отчёты остаются архивом, а не вторым актуальным roadmap.
- Текущий код и ограничения сверены read-only с реализацией. Отдельно указаны размер draft-пакета для MTP gate, точные границы vision-тестов, ограничения sampled-DFlash и незавершённая квалификация sampled-MTP. Неподтверждённые гарантии качества не перенесены как факты.
- Сводка результатов перенесена вручную с условиями и оговорками; личные изображения, ответы, сетевые сведения, исходные патчи с прежними метаданными не копировались в публичную документацию.
- Локальная памятка продолжения вынесена в игнорируемую `.local/HANDOFF.md`; она не является частью публичного Git и имеет отдельную локальную резервную копию.
- Сборка и аппаратные тесты в этом шаге не запускались. Первая публикация, GitHub SSH-аутентификация, перевод серверного клона и production-приёмка остаются незавершёнными.

### Подготовка собственной Git-истории

- Создан собственный форк `niiv0832/gufo-faex2`, отдельный локальный клон с историей Gufo и пятью изменениями.
- По явному согласию владельца до первой публикации заменены author/committer email пяти коммитов на GitHub noreply; имя, обе даты, сообщения и деревья файлов сохранены. Последний коммит реализации — `2c9c6b02`. Локальный email настроен только в этом репозитории.
- Известный личный адрес не найден во всей достижимой истории очищенной ветки. Это не общий аудит секретов. Старую историю не сливать обратно в опубликованную; её резервная копия остаётся непубличной.
- Интеграционная ветка — `faex2`; регулярное переписывание истории не планируется. Push на момент контрольной точки не выполнялся.

### Ускорение vision (`2c9c6b02`)

- Добавлены BF16-score hipBLAS-путь и fused WMMA attention; вариант encoder включён в cache identity, чтобы не переиспользовать прежние image-prefill результаты.
- Чистое время encoder в сохранённых тёплых прогонах: 8,65 → 1,99 с для синтетического скриншота, 18,56 → 3,56 с для 2048². 12 изображений прошли ограниченную функциональную проверку. Подробности и методика — [BASELINE.md](BASELINE.md).
- Численные тесты: малые N против CPU reference, большой N против BF16 BLAS. Первичный прогон со старым кэшем был отброшен. Универсальная эквивалентность качества не доказана.

### Поддержка зрения 35B-A3B (`6872f7a5`)

- Разрешён projector width 2048 и открытие encoder для qwen35moe с явным mmproj. Использован общий путь изображения/M-RoPE.
- 12/12 по набору владельца; прежде encoder был медленнее llama.cpp, затем ускорен отдельным изменением. Память с MTP1 и vision при 4 × 256K около 55,2 GiB GPU.

### MTP и DFlash2 (`cf39c57c`, `a41cccf6`)

- MTP: sampled proposals, полный словарь MoE по умолчанию, target-only шаг при слишком большом пакете черновиков. Добавлены policy-тесты. Выбран MTP1 по прозе и 1/2/4 запросам, а не максимуму coding throughput.
- DFlash2: MoE-калибровка стоимости и длина 0 с периодическими пробами. Быстрее прежнего adaptive на прозе, но всё ещё ниже off; эксперимент, не семейный default.
- Исправлена ошибка двойного продвижения MTP-cache при skip; повторный исторический прогон не дал прежних generation_failed. Оставшиеся ограничения runner/policy описаны в DESIGN.
- Исправления внешнего harness учли 2 запроса с sampling, корректный exit при readiness timeout и неприменимость cycle_ms при target-only шагах. Часть harness-ограничений ещё открыта.

### Сборка (`5409fdd9`)

- Сохранён обход несовместимости GCC 16/libstdc++ noinline в HIP-сборке. Candidate собирался отдельно от исходного бинарника, с тестами и без NPU.

## Правило последующих записей

На каждый законченный логический шаг: что изменено → как проверено → ограничения/решение → ссылки на код/доказательства. Не записывать «проверено» для непроведённых тестов. Изменение состояния реальной машины дополнительно фиксируется в её эксплуатационном журнале, но инженерный дизайн не дублируется там целиком.
