### Составлена карта NPU-стека (read-only анализ)

- Установлено и проверено через `git merge-base --is-ancestor`: весь XDNA2-стек vendor-линии (мерж `9982eaf6`, документация `3642b212`) уже является предком базы `6a107cf6`, то есть присутствует в ветке. Перенос из vendor не требуется; ранее сделанные в этой сессии противоположные выводы исправлены в самой карте.
- Стек выключен на двух уровнях (`GUFO_ENABLE_NPU` по умолчанию `OFF`, `GUFO_NPU_DIR` не задан). Причина — платформенный дефект Data Fabric Strix Halo ([NPU_FREEZE.md](NPU_FREEZE.md)): одновременный iGPU+NPU даёт deferred machine check MC28 и жёсткое зависание; AGESA 1.0.0.2b и FCLK-hold на Linux не подтверждены как фикс.
- Для 35B-A3B NPU ускоряет только prefill (замеры vendor: +1,1% @2K, +8,7% @4K, +9,5% @8K); decode остаётся на GPU. Собственные пять коммитов реализации форка не пересекаются по файлам с NPU-стеком, но сочетание NPU prefill с sampled-MTP форка не тестировалось.
- Проверены апстрим (стек удалён, есть документ с отклонёнными маршрутами), vendor после базы (8 NPU-коммитов: фикс безопасности `649824af` и серия jev-судьи), FastFlowLM (закрытые ядра, ниша — отдельный сервер для ASR/эмбеддингов) и llama.cpp-форк (0,6% утилизации AIE, PoC). Все пути переиспользования NPU упираются в один и тот же платформенный дефект.
- Создан [NPU_MAP.md](NPU_MAP.md); CONTEXT дополнен ограничением. Код и машина не трогались; коммит локальный, push не выполнялся.

### MTP и DFlash2 (`cf39c57c`, `a41cccf6`)

- MTP: sampled proposals, полный словарь MoE по умолчанию, target-only шаг при слишком большом пакете черновиков. Добавлены policy-тесты. Выбран MTP1 по прозе и 1/2/4 запросам, а не максимуму coding throughput.
- DFlash2: MoE-калибровка стоимости и длина 0 с периодическими пробами. Быстрее прежнего adaptive на прозе, но всё ещё ниже off; эксперимент, не семейный default.
- Исправлена ошибка двойного продвижения MTP-cache при skip; повторный исторический прогон не дал прежних generation_failed. Оставшиеся ограничения runner/policy описаны в DESIGN.
- Исправления внешнего harness учли 2 запроса с sampling, корректный exit при readiness timeout и неприменимость cycle_ms при target-only шагах. Часть harness-ограничений ещё открыта.

## Правило последующих записей

На каждый законченный логический шаг: что изменено → как проверено → ограничения/решение → ссылки на код/доказательства. Не записывать «проверено» для непроведённых тестов. Изменение состояния реальной машины дополнительно фиксируется в её эксплуатационном журнале, но инженерный дизайн не дублируется там целиком.
