4. Для продолжения настройки личного стенда прочитать **`.local/HANDOFF.md`**, если он существует в рабочем клоне. Это локальная, намеренно исключённая из Git памятка. В публичном клоне её отсутствие нормально; доступы не угадывать, запросить у владельца только несекретные сведения.
5. Перед изменением кода читать вложенные AGENTS в затрагиваемых каталогах. Перед обращением к реальной машине читать правила её эксплуатационного проекта, указанные в локальной памятке.

**Полный перевод согласован владельцем:** B2 (MTP1 + vision и расширенное качество), B3 (семейная нагрузка), C (сравнение/стабильность) и переключение существующего рабочего запуска выполняются самостоятельно по [плану приёмки](ACCEPTANCE_PLAN.md). Не запрашивать повторное согласие на уже разрешённые этапы. Push запрещён; сеть/sshd/firewall/ядро/BIOS/NPU и новый systemd/autostart вне задачи. Старый бинарник и откат сохраняются. Текущий этап — расследование B2-02: после исправления недоопределённого регистра в тесте, JSON Schema вызвал GPU memory fault в Q8 prefill kernel. B2 не пройден; оба прогона сохранены, серверы остановлены. [Результат](B1_RESULT.md): 9 запросов генерации и 4 discovery-запроса клиента PASS, базовые ответы проверены по goldens; off, 1×8192, без vision. Общее качество диалога/объяснений, MTP/vision, численная эквивалентность, сравнительная скорость и 24/7 пока не квалифицированы. ## 2. Проект

Клиенты последующих этапов подготовлены в `d21abee1`: семейный B3 и сравнение/soak C, 15+14 CPU-тестов PASS и независимое ревью. Их реальные запуски ожидают исправления GPU-сбоя B2; новые интерфейсы описаны в [HARNESS](HARNESS.md).

Узкий форк для Qwen3.6-35B-A3B со спекулятивным декодированием и зрением на FEVM FAEX2 128 ГБ (Ryzen AI Max+ PRO 495, целевой GPU gfx1151). Основной сценарий — русскоязычный семейный чат с несколькими агентами через общий API. Полный контракт и не-цели — [SPEC.md](SPEC.md).

- Собственный GitHub-форк: <https://github.com/niiv0832/gufo-faex2>.
- Непосредственная база (`vendor`): `mikealanni/gufo`, ветка `fork-enhancements`.
- Основной проект (`upstream`): `gufo-org/gufo`, ветка `main`.
- Интеграционная ветка проекта: **`faex2`**. Имена remotes — соглашение, не встроенные роли Git.
- Корневые `CHANGELOG.md`, большая часть README и `docs/` унаследованы от Gufo. **Наш журнал — `docs/faex2/CHANGELOG.md`.** Унаследованные NPU-результаты не являются нашими результатами на FAEX2.

## 6. Главные ограничения и стоп-сигналы

- 12/12 изображений и близость эмбеддингов — ограниченная проверка, не доказательство отсутствия всех потерь качества.
- Общий верификатор имеет p/q и residual sampling, но квалификация нового модельного sampled-MTP пути ещё не завершена. Не объявлять его распределение доказанно эквивалентным только по наличию формулы.
- DFlash2 с выборкой использует оценку стоимости C1 даже под большей нагрузкой. Для семейной прозы он проиграл `off` в сохранённых замерах.
- MTP gate относится к **размеру пакета предложений**, не просто к числу подключённых клиентов или слотов. Seed не гарантирует одинаковый текст при смене нагрузки.
- Некоторые прежние комментарии/планы устарели: после патча MTP MoE по умолчанию оценивает весь словарь. Старые планы не выполнять повторно.
- Внешний build-wrapper может вернуть успех при сбое сборки; перезапуски тестов могут смешивать результаты. См. [DESIGN.md](DESIGN.md).
- NPU-стек XDNA2 уже присутствует в ветке (унаследован от vendor-линии, мерж `9982eaf6` — предок базы `6a107cf6`), но выключен: `GUFO_ENABLE_NPU=OFF` и `GUFO_NPU_DIR` не задан. Причина — платформенный дефект Data Fabric Strix Halo: одновременный iGPU+NPU может вешать машину ([NPU_FREEZE.md](../NPU_FREEZE.md)). Выигрыш для 35B-A3B — только prefill (+1…+9,5%), decode без изменений. Карта статуса и условий пересмотра — [NPU_MAP.md](NPU_MAP.md).
- Никаких сетевых/системных изменений реальной машины без правил эксплуатационного проекта. Стабильность и доступ важнее скорости.
