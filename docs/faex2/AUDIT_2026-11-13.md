# Полный аудит доработок FAEX2 — рабочий протокол

Начат 2026-11-13. **Аудит продолжается; итоговый вердикт ещё не вынесен.**
Основание — поручение владельца проверить все доработки ради максимальной скорости
при сохранении качества Qwen3.6-35B-A3B. Разрешены тесты и сравнение других движков
на стенде без повторных согласований. Публикация и замена рабочего артефакта не
являются необходимой частью аудита.

## Объект и метод

- База собственного форка: `6a107cf6aeba7f28db266c2ba100bfb274f65e5a`.
- Полный охват также включает активную унаследованную основу: общий предок
  локального upstream и vendor — `d0f7c3a0`, до `6a107cf6` ещё 290 коммитов
  и diff 430 файлов. Собственные 135 файлов не заменяют аудит этой основы.
  Особое внимание: loader/переквантование, MoE prefill, router, batched verify,
  recurrent state и кэш. Отменённые и неиспользуемые этой моделью пути отделяются
  по текущим call sites, а не по именам каталогов или историческим сообщениям.
- Исследуемая вершина: `67da633f3da91855da7e06243fa847721b08ad54`;
  135 изменённых файлов. Реализация `src/`, CMake относительно `1195d154`
  не изменилась, после неё добавлены документы и тест снимка.
- Реальный рабочий бинарник подтверждён launcher: `1195d15427a43c45516ab9e7dd90777f8216b326`,
  SHA-256 `e319b5f5b5198dc60e089d8b57b3e8826728aed5b6ba9f1534adf0b18a67d607`.
  Четыре сеанса × 131072, MTP1, vision, reasoning budget 512.
- Независимо проверяются код численных ядер, runtime/API и пригодность прежних
  результатов. Отсутствие найденного дефекта не означает доказанную эквивалентность.
- Закрытый `OPTIMIZATION_BACKLOG.md` описывает выполненные эксперименты;
  он не заменяет приёмку по [SPEC](SPEC.md).

## Проверяемые требования и свидетельства

| Требование | Нужное свидетельство | Состояние на старте |
|---|---|---|
| Все сохранённые доработки | Карта diff → контракт → тест/численный результат | Независимые ревью идут |
| Корректность арифметики | Независимый reference, реальные формы, хвосты и несколько историй | Есть операторные тесты; общая гарантия не доказана |
| MTP и sampler | p/q/residual, greedy и sampled, EOS, tools, переходы 1/2/4, restore | Есть прежние проверки; последняя композиция требует проверки |
| Качество семейных задач | Обезличенные задачи с независимыми ответами; ошибки сохранены | Старые B2 содержат реальные FAIL |
| Скорость | HTTP, одинаковые веса/запросы/глубины/выход, прогрев, обе стороны | Прежнее сравнение llama относится к `00eddb85` |
| Параллельность/кэш | Реальные cache/prefill counters, очередь, TTFT/TTFA, wall, хвосты | Нужна проверка последнего состава изменений |
| Vision | Независимый энкодер и задачи, размеры/хвосты/несколько изображений | Ошибки крупных букв известны; smoke не доказывает качество |
| Надёжность | Отмена, обрывы, восстановление, ограниченный soak с монитором | Старый soak не относится к последнему бинарнику |
| Выбор движка | Совместимость, скорость, качество, память и ограничения альтернатив | llama готов для измерения; остальные исследуются |
| Итог | Согласие либо конкретный список доработок либо обоснованный другой движок | Не готов |

## Первый измерительный этап

Используется штатный `tools/bench/model-bench.py` из исследуемой вершины,
без изменения его критериев. Сборки: рабочий Gufo и уже собранный llama.cpp
`055c3c26efe6995c99344417ddedb2f54d1aeeb4`, HIP на том же TheRock 10.1.0,
один и тот же GGUF UD-Q4_K_XL. Этот pin служит воспроизводимым сравнением;
он не объявляется последней доступной версией.

Порядок: Gufo → llama.cpp → llama.cpp → Gufo. На каждой стороне AR и MTP1,
pp2048/tg128, глубины 0/16384/65536/120000, контекст 131072; MTP — проза и повтор.
Рассуждения выключены у обоих. C1/2/4 и память — отдельные штатные таблицы.
Любой отказ встроенной проверки сохраняется как отказ; успешные соседние строки
не превращают его в PASS. Полные команды, ошибки, температура и память сохраняются.
Профиль питания ОС отсутствует в sysfs; режим ECO 100 Вт известен из эксплуатационного
контекста, но не выдаётся за новое прямое чтение BIOS.

После остановки рабочего сервера прогон выполняется устойчиво к обрыву SSH.
Обёртка завершает только порождённые ею группы процессов и в `finally` возвращает
прежний рабочий запуск через его launcher. Настройки ОС, сеть и веса не меняются.
Сырые данные остаются непубличными. Следующие этапы выбираются по результатам,
включая содержательное качество, sampled MTP и нагрузку последней сборки.

## Предварительные находки

| Находка | Доказательство и последствия | Следующая проверка |
|---|---|---|
| Поздний общий префикс теряет checkpoint | `ShareCheckpoint` меняет список во время yield, после прохода `front()==prefill_offset` уже ложно; новая граница внутри прохода может скрыть и старую. Это лишнее чтение/задержка, не доказанная порча ответа | Настоящий CPU regression scheduler; пока проверены код и исполняемая симуляция |
| Не учтена память общего MTP scoring | `ScoreTogether` выделяет `8*(2048+248320)*4+8*4 = 8 011 808` байт на ведущего executor; `EstimateMemoryUsage`/`GetMemoryUsage` их не включают | Уточнить ресурсный контракт и проверить до/после первого общего scoring; OOM не наблюдался |
| Последняя sampled-MTP композиция не квалифицирована | Старые статистические наблюдения предшествуют shortlist/cohort4/shared-head. p/q/residual выглядит структурно корректно, но target verify и AR имеют известную разную арифметику | Независимые logits/PPL и интеграция C1/2/4, sampled, mixed-script, restore, EOS/tools |
| Изменение short-prefill оценено слишком узко | Семь из десяти текстов изменились; численная приёмка смотрела конечную позицию 23 уникальных коротких входов | Независимый задачный корпус и контроль коротких хвостов; изменение текста само по себе не означает ухудшение |
| Большая форма fused vision не имеет независимого oracle | N=11692 сравнивается с тоже изменённым tiled BF16; малые формы имеют CPU reference, есть прежние whole-encoder/задачные пробы | Уточнить достаточность прежних полных encoder результатов и недостающие реальные формы/задачи |
| Старые числа не описывают последнюю сборку | llama-сравнение было на `00eddb85`; старый soak — на `49f`. Shared-head +7–10% относится к сумме decode rates, а не ко всему запросу | Текущее сравнение и отдельная проверка рабочего профиля/устойчивости |
| Устаревший DESIGN меняет смысл повторения опыта | Удалённый `GUFO_MTP_VOCAB` и прежний default cohort2 могли создать ложный «контроль» | Документ исправлен; будущие опыты проверяют реальный scoring path |
| Не подтверждена ревизия прежнего prefill quality test | См. проверку ELF ниже; старый отчёт не сохранил путь/SHA фактически запущенного инструмента | Повторить проверку инструментом из закреплённых исходников с полным manifest |

Кодовые места: [ShareCheckpoint и Prefill](../../src/cli/serve/text_model_runner.cpp),
[admission внутри yield](../../src/cli/serve/text_generation_scheduler.cpp),
[ScoreTogether и учёт памяти](../../src/models/qwen/hip/mtp/executor.cpp).
Подробные локальные ревью и воспроизводящие материалы сохранены отдельно;
их заключения сверяются с исходниками и прямыми тестами перед итоговым вердиктом.

CPU-проверки FAEX2 harness выполнены на Mac: 143 теста, из них 104 сразу прошли,
39 не смогли открыть тестовый loopback-сокет из-за sandbox; только эти 39 повторены
вне sandbox и прошли. Это проверка валидаторов/транспорта, не модели. Полная
проверка Markdown-ссылок обнаружила прежнюю отсутствующую `NPU_FREEZE.md`
в историческом журнале; новые ссылки аудита разрешаются.

Подтверждённые положительные результаты также учитываются: исправление Q8 fault,
разделение scratch по GPU streams, побитные операторные проверки group8 attention
и MoE tail, snapshot roundtrip, сохранённые отрицательные эксперименты и откаты.
Строгие задержки `49f → d891354f` были закрыты в [CLOSURE_RESULT](CLOSURE_RESULT.md);
старое `INCONCLUSIVE` другой пары нельзя переносить на все версии.

### Проверка происхождения численного инструмента

В 02:50–02:51 MSK 2026-11-13 прочитан существующий `qwen35moe_gpu_logits_tool`
из сборочного каталога предыдущих экспериментов. SHA-256:
`a5e8cf449eed804b526da45306db8dc7ed3fd3c2f599f8ae0c7ee872422adffc`.
`nm -C` показывает `LaunchResidualAddRMSNorm(..., unsigned long, void*)` —
сигнатуру отменённого опыта `1b1dfa80`. У рабочего бинарника `1195d154` эта
функция заканчивается `..., unsigned long)` без дополнительного указателя.
Разница совпадает с исходным diff опыта и его отмены. Ninja подтверждает линковку
инструмента в 18:57:35; последующая пересборка `libgufo_core.a` в 19:25 сама по себе
не перелинковала этот executable.

Таким образом, текущий найденный инструмент **не соответствует реализации
рабочего `1195d154`**, хотя его source-каталог уже содержит отмену опыта.
Прежний `quality-long.sh` принимает путь инструмента аргументом, не печатает его
или SHA и подавляет stderr вызовов. В сохранённых результатах замера 19:27–19:35
конкретный путь аргумента не найден. Поэтому утверждение прежнего отчёта
«инструмент собран из того же кода, что `1195d154`» **не подтверждено**.
Это не доказательство того, что тот запуск точно использовал найденный stale
executable; достаточно отсутствия проверяемой привязки, чтобы снять с результата
роль свидетельства для `1195d154`. Рабочий бинарник не затронут.

## Альтернативы для проверки

Первый прямой конкурент — llama.cpp HIP, затем Vulkan на том же SHA/весах.
Существование другого backend не доказывает его превосходство. vLLM и SGLang
нельзя исключать по предположению об отсутствии gfx1151: актуальные
[инструкции vLLM](https://docs.vllm.ai/en/latest/getting_started/installation/gpu/)
и [SGLang](https://github.com/sgl-project/sglang/blob/main/docs/docs/hardware-platforms/amd_gpu.mdx)
это железо учитывают. Однако [GGUF в vLLM](https://docs.vllm.ai/en/latest/features/quantization/gguf/)
экспериментален; смена формата/квантования требует отдельной проверки качества.
В [README ik_llama.cpp](https://github.com/ikawrakow/ik_llama.cpp/blob/main/README.md)
полная работоспособность/производительность заявлены для CPU/CUDA, поэтому для
этого iGPU он ниже в очереди проверки. Ссылки изменяемые; перед запуском требуется pin.
