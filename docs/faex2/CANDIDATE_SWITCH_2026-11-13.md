## Переключение, проверка API и возврат

Старый процесс останавливается **старым** launcher; только после подтверждения
остановки устанавливается новый комплект. Использовать проверенный generated
`cutover.sh` в устойчивом сеансе и сохранить весь журнал. Штатный профиль
запуска — `fork_restart.sh mtp1 4 131072 mmproj`. Автоматический возврат этого
сценария при ошибке старта/отсутствии READY — лишь первая защита: поздняя ошибка
API, identity или дискового восстановления тоже требует возврата.

После READY проверить полный SHA, `/proc` executable, owner/child identities,
точный launcher request, `/health`, `/v1/models`, `/slots` и прежний bind.
Проверить ответ `56`, настоящий вызов `get_weather` с городом `Казань`,
синтетический красный квадрат, SSE и JSON без утечки служебного framing,
фактические proposed/accepted MTP drafts и независимость сеансов.
Использовать исправленный клиент приёмки и сохранять запросы/ответы.
Исторические `verify.py` и `disk_check.py` из v13 печатают результаты;
их exit 0 без проверки содержимого и счётчиков не является PASS.

До признания перевода завершённым проверить реальный путь возврата:
остановить candidate, запустить сохранённый `1195d154` через **новую роль
recovery**, проверить SHA/READY и API, затем штатно остановить recovery.
Если возврат прошёл и остальные ворота остаются зелёными — вернуть candidate
как main и повторить проверки. На самом стенде, с уже проверенным новым
launcher, поддерживаемый селектор имеет вид:

```bash
env GUFO_BIN="$HOME/gufo-release/1195d154-e319b5f5/bin/gufo" \
  "$HOME/bin/fork_restart.sh" mtp1 4 131072 mmproj
```

Статус и остановка recovery выполняются с тем же `GUFO_BIN` и существующими
`--status`/`--stop`. Флага запуска `--role` эта процедура не вводит.
Если новый launcher сам неисправен, после остановки принадлежащих ему
процессов восстановить три файла из проверенного backup, сверить их SHA и

Кандидат использует `qwen-bf16-fp32-prefill-v2`. Это версия **численной
совместимости**, не номер формата файла snapshot. Старые состояния рабочего

Не переименовывать их identity и не переносить их вручную в новый namespace.
Новый namespace начинает отдельную историю кэша; прежний сохраняется для
возврата без пересборки.

На кандидате создать собственное состояние, дождаться подтверждения записи,
перезапустить именно тот же бинарник и проверить disk hit, ответ, identity и
учёт токенов. Для raw completion zero-prefill требуется ровно ноль; для chat
сверять зарегистрированную границу snapshot, не называть остаточный prefill
нулевым. Проверить отказ восстановления несовместимого старого состояния.

persistence; обходить эту защиту ради приёмки нельзя.
